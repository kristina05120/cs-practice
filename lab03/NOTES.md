git diff — показывает разницу между состояниями: что именно изменилось.

git show — показывает один объект: чаще всего коммит целиком, либо тег, дерево, файл.

git log — показывает историю коммитов (хеш, автор, дата, сообщение), без diff'а по умолчанию.

git log -S "строка" — ищет коммиты, в которых эта строка появилась или исчезла.

git blame — показывает по каждой строке файла, какой коммит и какой автор последний раз её меняли.



git restore <file> возвращает файл из индекса (staging) в рабочее дерево — откатывает незастейдженные правки; если файла в индексе нет, берётся версия из HEAD. git restore --source=<commit> <file> берёт версию файла из указанного коммита и кладёт её в рабочее дерево и индекс — можно вернуть файл из любого момента истории, а не только из HEAD. В обоих случаях незакоммиченные правки в этом файле теряются безвозвратно, а уже закоммиченная история не затрагивается.



git revert не удаляет старый коммит, а создаёт новый, который отменяет его изменения — история сохраняется. git reset --hard переписывает историю: сдвигает ветку назад и безвозвратно стирает коммиты и правки после целевого. В опубликованной истории безопаснее revert, потому что он пушится как обычный коммит без force-push и не ломает историю у коллег, тогда как reset --hard требует force-push и рассинхронизирует их копии.
